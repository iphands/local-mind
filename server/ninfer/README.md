# ninfer — NInfer for Qwen3.8-Flash-Next on the RTX PRO 6000

[NInfer](https://github.com/Neroued/ninfer) (a from-scratch C++/CUDA engine that targets
`sm_120a` only), built from a pinned commit in our own container, serving Qwen3.8-Flash-Next on
`:8700` — the same port and model alias (`cosmo-6000`) as the vLLM daily driver in
`../vllmcustom`, so `llama-proxy` needs no change. The goal is the fastest single-stream decode
this card can do, measured against vLLM FP4-Local.

**Status:** under construction (Plan 01, `context/plans/`). Nothing here has been built,
converted or booted yet; every number this project cites will live in the plan tracker's
Evidence table.

## Prerequisites

- Docker reachable **as yourself** — no `sudo` anywhere. Every script refuses a `DOCKER` that
  names `sudo` and refuses to run as root. Containers run as uid/gid `1000:1000`.
- The RTX PRO 6000 as CUDA device 0, driver with the CUDA 13.4 UMD (615.78.08 on 2026-10-27).
- ~63.3 GiB of host RAM free for the registered expert backing, on top of the system.
- `models` → `/mnt/noir/scratch/ai/llm/models` (the siblings' model tree).
- **One server on `:8700` at a time**: stop vLLM (`docker stop vllm`) before converting or
  booting NInfer. Both need the GPU.

## The three steps

The long and GPU steps are run by the owner; the scripts refuse to start in a state they cannot
finish from.

1. **Build the image** — `./build`.
   - Clones `vendor/ninfer` on first run (blobs on demand), refuses if it is dirty, checks out
     `NINFER_SHA` detached, and builds `iphands/ninfer-blackwell:cu1343-sm120a-64d10fb` with
     `JOBS` = half the cores. The log goes to `captures/build_<date>_<sha7>.log`; the script prints
     the image ID and its `ai.ninfer.*` labels at the end.
   - `PREFLIGHT_ONLY=1 ./build` does every check (checkout, both base digests, `docker build
     --check`) and prints the build command without building.
2. **Download the BF16 base, then convert** — `./scripts/convert`.
   - Our NVFP4 checkpoint (`models/vllm/nvidia/Qwen3.8-Flash-Next-NVFP4`) is the recipe's `nvidia`
     source, not its base; the BF16 base `Qwen/Qwen3.8-Flash-Next` (360 GB) is required. With no
     base on disk, `./scripts/convert` refuses and prints the exact download command — `hf` from
     the converter image, since the host has none.
   - Stop vLLM first; the script refuses while `vllm` (or anything on `:8700`) runs. It checks
     both checkpoints' headers (BF16 bank and PLE in the base, 48 NVFP4 expert layers and 294,912
     expert keys in the NVIDIA one), that the output does not exist, and ≥ 110 GB free.
   - The conversion runs in `../vllmcustom`'s image on the GPU, as uid 1000, with no network, and
     writes `models/ninfer/qwen3.8-flash-next/qwen3_8_flash_next.ninfer` + `.part-NNNN` files +
     `.conversion.json`. The log is `captures/convert_<date>_<name>.log`, ending with the
     converter's peak RSS and the wall time.
   - `DRY_RUN=1 ./scripts/convert` does every check and prints the command without running it;
     `INSPECT=1 ./scripts/convert` inspects the finished artifact (no GPU).
3. **Serve** — `./run` on `:8700` *(added in Plan 01 T5)*.

## Layout

| Path | What |
|---|---|
| `versions.env` | every pin: NInfer SHA, CUDA base images by digest, image name, BF16 base revision |
| `lib/common.sh` | shared guards (DOCKER/sudo/root/socket) and helpers, sourced by every script |
| `seccomp/ninfer.json` | docker's default seccomp profile + the 3 io_uring syscalls NInfer needs; generated by `scripts/seccomp-profile` (see `seccomp/README.md`) |
| `Dockerfile`, `build` | the two-stage image (CUDA 13.4.3 devel → runtime, `sm_120a`, `USER 1000:1000`) and the script that pins and builds it |
| `scripts/convert` | containerized `tools.convert` (BF16 base + NVIDIA NVFP4 → `.ninfer`), header preflight, `INSPECT=1` |
| `models` | symlink to the shared model tree |
| `vendor/ninfer` | the pinned NInfer checkout `./build` manages (gitignored, read-only) |
| `captures/` | bench output and logs (gitignored) |
| `context/` | the project's knowledge base and plans (`context/plans/RULES.md` governs work) |
