# Plan 02 T3 · negative controls on the census harness — every assertion shown capable of firing, 2026-11-05

Subject: `context/audit/scripts/t3-census.sh`, `GENERATOR_SHA256=1bab1ec5e7933c90a80a97aa875218351052280445d585bfce6645f036128106`
(the frozen generator; the same token heads [`t3-sentinels-real.txt`](t3-sentinels-real.txt)).

**Read this line first.** All ten controls below fired. The two failures that actually happened in
this work are **§ 3** (my own batch ate its own evidence) and **§ 4** (a control run under `tag=real`
destroyed the real run's artifacts). Read those two before trusting any green thing here.

## Why this file exists

RULES.md: a tool's clean output is worthless until it has been shown to report something. `34/34 PASS`
on the real tree says nothing on its own — one of those 34 was *already known* to be a tautology
(`SORT_DEFAULT_ORDER_EQ_C`'s first cut compared `sort` output to `"Bab"` inside a process that had
exported `LC_ALL=C` twelve lines earlier) and three more were strict logical implications of their
neighbours. Knowing the count and checking the count are different acts; the same goes for knowing an
assertion *could* fail.

## Method — three rules, each learned by getting it wrong

1. **The repo script is never mutated.** A copy is made **beside the original**
   (`context/audit/scripts/.neg-<name>.sh`), run from the project root, and deleted after. Reason: the
   script resolves `MAN`/`PROJ` from its own location (`$SELF`); a copy parked in `/tmp` resolves the
   manifest to `/tmp/manifest` and dies at `MANIFEST_DIR_NOT_FOUND` (exit 2) **before any assertion
   runs** — which reads like a control that failed to fire rather than a control that never ran.
2. **The mutation is an exact-string replacement that must match exactly once**, else the harness
   refuses with `VACUOUS n=<count>` and runs nothing. A `sed` that silently matches nothing produces a
   clean run of an *unmodified* script — the worst possible control, because it reports green about
   green. Byte-difference from the original is therefore guaranteed before execution.
3. **A control passes only if: exit 1, `T3_CENSUS_VERDICT=FAIL`, and the named assertion's own line
   reads FAIL.** A run that dies at exit 2 is a broken control, not a fired one.

Scope of what is covered: **10 of the 34 assertions**, all on the `real` path. Scale per control is
stated in its header (`maximal` = the mutation inverts a whole-set comparison so every row fails; that
is full-scale liveness, not single-row discrimination). `GENERATOR_SHA=` on each block is the **mutant's
own** printed token — the only thing that identifies which program emitted that stdout.

### C7 — the sort-order comparator fed reverse-C order  ·  tag=negctl  exit=1  fails=2  ·  comparator only

**`bBa` is not a locale output and must not be read as one.** `LC_ALL=C` gives `Bab`; a realistic
non-C collation gives `aBb`; `bBa` is simply reverse-C order, so this mutation exercised the
**comparator**, not the `LC_ALL=C` export the assertion exists to police. The export half is
**unfireable on this host and a genuine export drop can PASS here**, because glibc resolves an unknown
locale to C and `LC_ALL=en_US.UTF-8 sort` was measured to emit `B a b`, identical to C. See
`context/pitfalls.md` § *An LC_ALL naming a locale the host does not have falls open to C — no warning,
no error*.

**Wiring-only, and that is a real limitation.** With both legs equal, the verdict is decided by an
equality the same process guarantees, so the failure this assertion exists to catch — two genuinely
*different* predicates meeting an intact `eq` — is never exercised. The better mutation changes the
*other leg's input* and keeps the operator: one byte in a mutant's `families.tsv` heredoc moves
`PRED_SHA`. Not run. **C10 below is the model this one should have followed.**

### The compare that controlled itself for free

`GENERATOR_SHA_SAME_AS_REAL` fired on **C3–C10 without being touched**: each mutated copy is a
different program, so every canary-tag run disagrees with `run-real/generator.sha256`. That is the
intended signal, and it is why every block above names its own mutant hash. C2 legitimately did not
fire it — C2 ran as `tag=real`, where there is no self-compare. C1 did not fire it either: it ran while
`run-real` was missing, and took the `GENERATOR_SHA_AVAILABLE` failure branch instead.

## 2 · What is NOT controlled

Stated because an unlisted gap is a gap someone fills by guessing.

- **No canary control exists.** Six planted primitives, one per class, do not exist yet. Until
  `t3-canary-score.tsv` has 6 rows the census cannot print plain `PASS`. By design, not oversight.
- **C7's locale arm** (above): unfireable here, and an export drop can pass.
- **`FIND ENTITY_GRANULAR_ROWS_WITHOUT_LINE_EVIDENCE` has no chk.** The literal `1` that S14/S15/S18
  write into column 6 (headed `hits_in_file`) is disclosed, not asserted: comparing it against a
  constant is the tautology this harness has been deleting all cycle, not one it should mint.
- **`FIND SENTINEL_TOTAL_FLOOR_NOT_MEASURED` has no chk either** — see the next bullet, which is worse.
- **The canary tag floors nothing.** The floor is `[ "$TAG" = real ]`-gated; on every other tag the
  script prints a `FIND` line, which is a display and not a failure. Measured: `SENTINEL_TOTAL=28` on
  `negctl` against 34 on `real`, because the real-only assertions (the manifest gate,
  `UNIVERSE_*_EQ_PIN`, `LOC_*`, `GRANULARITY_FORCE_IS_FIRED`, the two collapse assertions) are absent
  there. Consequence, plainly: **a canary run that silently loses assertions still prints PASS.** The
  floor constant for a canary tag has to be measured on the first real canary run; guessing it would
  repeat the floor-of-31 mistake below.
- **`SENT_TOTAL_FLOOR_REAL` was guessed as 31 on the first cut and passed by luck** against a different
  quantity (the pre-increment `SENT_TOTAL`), printing `SENTINEL_TOTAL=31` above a verdict line saying
  "32 assertions met". The floor is now compared against `$((SENT_TOTAL+1))` for exactly that reason.
- **Never assert arithmetic between `SENTINEL_TOTAL` and `SENTINEL_FAILS`.** Four sites (the
  `TREE_DIFF_AVAILABLE`, `GENERATOR_SHA_AVAILABLE`, `INPUTS_SHA_AVAILABLE`, `PREDICATE_SHA_AVAILABLE`
  branches) add to `FAILS` without adding to `TOTAL`, so `TOTAL − FAILS` is not a pass count. C1's
  footer is this asymmetry in the wild.
- The 24 assertions not covered by C1–C10 are uncontrolled. Most are value-comparisons against a
  constant measured in the same run (`LOC_EQ_PIN_CONSTANT`, `UNIVERSE_*_EQ_PIN`) and inherit their
  weakness from the pin's own provenance, recorded in `wave0/t1-freeze-and-manifest.txt`.

## 3 · My own batch, and the false alarm it produced  [OBSERVED 2026-11-05]

The first control batch was launched from `context/audit/scripts/` instead of the project root. Every
run died at `cd "$ROOT"` with **exit 2** — `$ROOT` is `vendor/basalt`, a path relative to the project
root. Eight "controls" reported nothing at all.

That batch's earlier attempt had parked its copies in `/tmp`, where the script's `MAN`/`PROJ`
resolution points at `/tmp/manifest` and `/tmp/…/plans/…`; those runs died at
`MANIFEST_DIR_NOT_FOUND` / `PLAN_NOT_FOUND`, exit 2, before any assertion. Because the census opens
with `rm -rf "$RUN" "$OUT"`, and because at least one of those mis-launched runs carried `TAG=real`,

therefore printed:

`tn_invert`, `sort_unsorted`, `nosort`, `s14_empty`, `pred_invert`, `inputs_diff`), and C1 — the one

## 4 · A control that runs under `tag=real` overwrites the real run's baseline  [OBSERVED 2026-11-05]

`RUN=/tmp/opencode/basalt-audit/t3/run-$TAG` is wiped at start, and `run-real` is what every
canary-only compare reads as its reference. **C2's floor assertion is `tag=real`-gated**, so C2 had to
run under that tag — and it replaced `run-real`'s tokens with a **mutant's**:

    run-real/generator.sha256 became  b75fd2f0fa0c1097…   (= C2's own GENERATOR_SHA256, verified above)

That value is the "expected" leg printed in C3–C10's `GENERATOR_SHA_SAME_AS_REAL` failures. **It is a
contaminated baseline and is quoted as such; it is not a reference.** It does *not* invalidate those
controls' FAIL results — a mutant differs from another mutant, so liveness is still demonstrated — but
no baseline figure from that window should be reused.

The rule taken from this: **no control runs under `tag=real` again; a `real`-gated assertion is
executed last, in a batch whose output is discarded.**

Restore, proved by reproduction rather than by assertion. `run-real` is regenerable by design, so the
claim is not "I salvaged it" but **"a pristine re-run reproduces the pasted evidence exactly."** After

## 5 · Three-leg freeze check, after every run on this page

The census reads the tree and writes only under `/tmp/opencode/basalt-audit/t3/`; the mutated copies
were created inside `context/audit/scripts/` as `.neg-<name>.sh` **and deleted** (`git status
--porcelain` over the repo after each batch: no residue). So the audited tree was never written to —
which is the claim the plan's single-leg `git diff` version of this check could not actually support:

    $ cd vendor/basalt
    $ GIT_NO_LAZY_FETCH=1 git diff --quiet dc047a77beeddf1e91234d983a91d6bf929e9619 && echo "AUDIT TREE OK (tracked contents)" || echo "AUDIT TREE DRIFTED — STOP"
    AUDIT TREE OK (tracked contents)
    $ N=$(find . -type f -not -path './.git/*' | wc -l); [ "$N" -eq 862 ] && echo "TREE FILE COUNT OK (862)" || echo "TREE FILE COUNT=$N — untracked additions — STOP"
    TREE FILE COUNT OK (862)
    $ U=$(git status --porcelain --ignored | grep -c .); [ "$U" -eq 0 ] && echo "TREE CLEAN (no untracked/ignored)" || { echo "TREE NOT CLEAN: $U entries — STOP"; git status --porcelain --ignored | head; }
    TREE CLEAN (no untracked/ignored)

Why three legs and not one: `server/basalt/.gitignore` line 1 is `/vendor/`, so `git diff <pin>`
compares tracked contents and cannot see an ignored untracked file. That is the whole of
[`t3-tree-contamination.txt`](t3-tree-contamination.txt).
