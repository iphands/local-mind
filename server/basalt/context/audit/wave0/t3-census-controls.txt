## Method — four rules, each learned by getting it wrong

1. **The repo script is never mutated.** A copy is made **beside the original**
   (`context/audit/scripts/.neg-<name>.sh`), run from the project root, and deleted after. Reason: the
   script resolves `MAN`/`PROJ` from its own location (`$SELF`); a copy parked in `/tmp` resolves the
   manifest to `/tmp/manifest` and dies at `MANIFEST_DIR_NOT_FOUND` (exit 2) **before any assertion
   runs** — which reads like a control that failed to fire rather than a control that never ran.
2. **The mutation is an exact-string replacement that must match exactly once**, else the harness
   refuses with `VACUOUS n=<count>` and runs nothing. A `sed` that silently matches nothing produces a
   clean run of an *unmodified* script — the worst possible control, because it reports green about
   green. Byte-difference from the original is therefore guaranteed before execution.
3. **A control passes only if: exit 1, `T3_CENSUS_VERDICT=FAIL`, and the named assertion's own line
   reads FAIL.** A run that dies at exit 2 is a broken control, not a fired one.
4. **What the per-block `GENERATOR_SHA=` tokens are actually backed by — a withdrawal, 2026-11-05.** A
   draft of this header claimed every token was re-derivable as `sha256(frozen base + the printed
   one-substitution)`, which would have made the scratch transcripts unnecessary. **That claim is false,
   and it was tested the same day it was written.** Measured: each `mutate:` pair's left-hand side occurs
   **exactly once** in the frozen script (10 of 10 — the recipes locate correctly, so this is not a
   transcription failure of that kind), but re-deriving from the frozen base reproduces **0 of the 9**
   re-derivable tokens (C1's is `deadbeef` by construction and is excluded). The base was **not** the
   frozen script. The clean case is C2: its mutation is a one-token change on a standalone line
   (`SENT_TOTAL_FLOOR_REAL=34`, unique in the file), so if its base had been `1bab1ec5…` its token would
   follow arithmetically — it does not. And `context/audit/scripts/t3-census.sh` carries **mtime
   2026-11-05 06:35:10**, i.e. after the last control in this file ran (06:35:08) and four seconds before
   the `real` run this plan pastes (06:35:14): **the generator was rewritten after this batch was
   collected.** *(Those three timestamps are an on-host observation — `stat` output from 2026-11-05, not in
   git and unverifiable by any later reader. The conclusion does not rest on them: exactly one blob of this
   file has ever been committed, `1bab1ec5…`, and it is not the base the ten originals were cut from.)* The bytes these ten mutants were cut from are unrecoverable — exactly one blob of that
   file has ever been committed (`1bab1ec5…`), and the mutant copies that rule 1 requires are deleted
   after each run, per rule 1.

   A second key now sits in every block, and it is *not* a transcription: **`REBUILT_SHA=` is the sha256 of
   the program `context/audit/scripts/t3-make-mutant.py` builds from that block's own `mutate:` pair,
   against `1bab1ec5…`** (added 2026-11-05). `GENERATOR_SHA=` remains what a run printed and stays
   untouched; `REBUILT_SHA=` is the recipe's identity, it is asserted by the applier on every build (exit
   7), and it is what makes § *Re-fire* mechanical rather than ten rows a human compares by eye. It also
   ends the one gap rule 4 leaves: C1 prints `deadbeef` instead of its own hash, so before this key its
   program was recorded **nowhere** — and the only place it was written down was a generated paste that
   says "never hand-edit, replace whole". The applier grants C1's short token only when the block states a
   `REBUILT_SHA=`, so a copied block that keeps the poison and drops the identity is refused rather than
   waved through. Placed **above** `mutate:` deliberately: the applier captures from `mutate:` to
   `GENERATOR_SHA=`, so a key inside that span silently becomes part of the fixture (it did, to all ten).

## 4 · A control that runs under `tag=real` overwrites the real run's baseline  [OBSERVED 2026-11-05]

`RUN=/tmp/opencode/basalt-audit/t3/run-$TAG` is wiped at start, and `run-real` is what every
canary-only compare reads as its reference. **C2's floor assertion is `tag=real`-gated**, so C2 had to
run under that tag — and it replaced `run-real`'s tokens with a **mutant's**:

    run-real/generator.sha256 became  b75fd2f0fa0c1097cf6b67181c8920126f302725dc1f3b737c90d54a5e25e7ad
      (= C2's own GENERATOR_SHA256; the two strings MATCH AS TYPED — both were transcribed from terminal
       output, so no byte-comparison was ever performed between them. The comparison that WAS machine-run
       is C9's, described in § Method rule 4.)

That value is the "expected" leg printed in C3–C10's `GENERATOR_SHA_SAME_AS_REAL` failures. **It is a
contaminated baseline and is quoted as such; it is not a reference.** It does *not* invalidate those
controls' FAIL results — a mutant differs from another mutant, so liveness is still demonstrated — but
no baseline figure from that window should be reused.

The rule taken from this: **no control runs under `tag=real` again; a `real`-gated assertion is
executed last, in a batch whose output is discarded.** Read it as the procedure it is, not as a ban on

last in the batch, its output discarded, then `run-real` restored and verified — and it fired. Add one clause
that this incident makes obvious: **when the control writes into the baseline's namespace, the aside-copy is
mandatory, not "output discarded" alone.** The evidence: [`t3-negctl-rechecks.txt`](t3-negctl-rechecks.txt)
§ C2, which shows what the run overwrote and what the restore proved.

## 5 · Three-leg freeze check, after every run on this page

The census reads the tree and writes only under `/tmp/opencode/basalt-audit/t3/`; the mutated copies
were created inside `context/audit/scripts/` as `.neg-<name>.sh` **and deleted** (`git status
--porcelain` over the repo after each batch: no residue). So the audited tree was never written to —
which is the claim the plan's single-leg `git diff` version of this check could not actually support:

    $ cd vendor/basalt
    $ GIT_NO_LAZY_FETCH=1 git diff --quiet dc047a77beeddf1e91234d983a91d6bf929e9619 && echo "AUDIT TREE OK (tracked contents)" || echo "AUDIT TREE DRIFTED — STOP"
    AUDIT TREE OK (tracked contents)
    $ N=$(find . -type f -not -path './.git/*' | wc -l); [ "$N" -eq 862 ] && echo "TREE FILE COUNT OK (862)" || echo "TREE FILE COUNT=$N — untracked additions — STOP"
    TREE FILE COUNT OK (862)
    $ U=$(git status --porcelain --ignored | grep -c .); [ "$U" -eq 0 ] && echo "TREE CLEAN (no untracked/ignored)" || { echo "TREE NOT CLEAN: $U entries — STOP"; git status --porcelain --ignored | head; }
    TREE CLEAN (no untracked/ignored)

Why three legs and not one: `server/basalt/.gitignore` line 1 is `/vendor/`, so `git diff <pin>`
compares tracked contents and cannot see an ignored untracked file. That is the whole of
[`t3-tree-contamination.txt`](t3-tree-contamination.txt).
