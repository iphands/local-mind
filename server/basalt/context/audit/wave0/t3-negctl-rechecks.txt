Raw output. **Never hand-edit this file: replace it whole, or leave it.** Commentary is marked `>`;

**And one rule about machine-format values in prose** — a `KEY=value`, a hash: in prose or

refutes is quoted with typographic marks and refuted on the line beneath it, never restated in
machine form, because grep returns lines and cannot tell an asserted figure from a repudiated one
(`context/pitfalls.md` § *Provenance that cannot contradict its own claim*).
**Exempt: everything copied, and coordinates.** Indented transcript blocks and the per-control rows of
the tables are outputs, and outputs repeat themselves — twelve runs in the blocks below print the
verdict line, which is why it appears twelve times there and three times above them. A `path:NNN` is a

table naming a site its bullets then discuss). **Never de-duplicate a raw block to satisfy the rule
above — fidelity outranks uniqueness there, and the damage is invisible.** Coordinates are held to the
inverse instead: **no site gets two coordinates in this file.**

## § 3 · Reproducibility — the finding that was not asked for

Two independent batches of the same ten recipes against the same frozen base (the first at 07:02-07:04,
the second at generation time). Per control: same program, and same stdout modulo the two lines that
are timestamps by construction (`== t3-census.sh started=…`, `== finished=…`). **The exclusion is
self-checking: each transcript must shed exactly those two lines, or the emitter refuses to write.**

## § 3b · Re-fire — the rebuilt-program column needs nothing but the tree

Reproducibility above compares two batches, both of which live in scratch that is going away. This
subsection is the claim a reader can recompute alone: rebuild each control program from the recipe
**as the repo currently holds it** and hash it. Scope, precisely: **the rebuilt-program column is**
reproducible from files in this repo and nothing else. **The normalized-stdout column is not** —
reproducing it means *running* the ten mutants against `vendor/basalt` at `dc047a77` with a `run-real`
baseline present, including C2 under `tag=real`, which **writes `run-real`**. Follow
`t3-census-controls.txt` § 4’s aside-copy-and-restore procedure first, or do not run them.

Run from the project root. Four things in this loop are deliberate, and three of them are defects
earlier versions of it actually had; the `>` note under the table carries all four. The expected
base hash is a **pinned literal**, not derived from the file under test: deriving it from
`t3-census.sh` and comparing it against `t3-census.sh` is a hash compared against itself, which is
what the first version did, so the gate could never fire on a moved generator. The **preflight**
counts the rows the selection pattern finds and refuses to compare at all unless it is exactly ten,
because a per-row check inherits the emptiness of its own extraction. Each row **tests** its own
hash against column 2 below, so the fence fails by itself instead of printing ten numbers for a
human to compare. And the expected hash is read from **this file**, not from
`t3-census-controls.txt` — the controls file is machine-enforced by the applier, so checking a build
against it would be a tautology. The value here is the cross-check against the one document that is
*not* enforced, which is the table below. The scratch directory goes with the `trap`.

```bash
set -euo pipefail
out=$(mktemp -d); trap 'rm -rf "$out"' EXIT
FROZEN=1bab1ec5e7933c90a80a97aa875218351052280445d585bfce6645f036128106
SRC=context/audit/wave0/t3-negctl-rechecks.txt
rows=$(grep -c '^| C[0-9]\{1,2\} | .*`[0-9a-f]\{64\}`' "$SRC" 2>/dev/null || true)
rows=${rows:-0}
[ "$rows" = 10 ] || { printf '§ 3b rows selected: %s (expected 10) — refusing to compare\n' "$rows" >&2; exit 1; }
ok=0; fail=0
for c in C1 C2 C3 C4 C5 C6 C7 C8 C9 C10; do
  python3 context/audit/scripts/t3-make-mutant.py \
      context/audit/wave0/t3-census-controls.txt \
      context/audit/scripts/t3-census.sh "$out/$c.sh" "$c" \
          "--expect-sha=$FROZEN" > /dev/null
  got=$(sha256sum "$out/$c.sh" | cut -d' ' -f1)
  pat='^\| '"$c"' \| `[0-9a-f]{64}` \| '
  want=$(grep -E "$pat" "$SRC" | sed -E 's/^\| [^|]+ \| `([0-9a-f]{64})`.*$/\1/' || true)

  else printf '%s  MISMATCH got=%s want=%s\n' "$c" "$got" "$want"; fail=1; fi
```

## § 7 · State legs, because a partition is state-scoped

Four mechanisms decide which labels a run prints and what its footer says. All four are in the
generator; none of them is described in this file well enough to be trusted from description, which
is why the last third of this section is measurements. The table is the whole shape in one screen;
the bullets after it carry only what the wording has already gotten wrong once. The fifth row is not
a fifth mechanism — it is a hazard sitting on the first one’s line.

Bare `:NNNN` in this section means `context/audit/scripts/t3-census.sh` at the frozen `1bab1ec5…` cut
and only that cut; the same file at a later commit has different numbers.

| Mechanism | Where (in `t3-census.sh`) | What it moves | Measured here? |
|---|---|---|---|
| Column-6 state gate | `:1448`–`:1451` | which **name** prints, and whether it is counted | no — unobservable until the fill |
| `tag` coordinate | `:222`, `:259`, `:401` | the **name-set**: 11 real-only, 5 non-`real`-only | § 6 recomputes it |
| `run-real` artifact legs | `:259`, `:277`, `:285`, `:402` | those same 5 names, **and** the footer count | yes — the two states below |
| `UNIVERSE_SHA_MATCHES_PIN` | `:246` | **counted vs merely displayed**: prints always, counts once | § 6 note (1) |
| The hardcoded `862` | `:1448`, against `EXPECTED_UNIVERSE` at `:234` | can flip the gate for an unrelated reason | no — flagged from the source |

- **The column-6 state gate — two *different* names, not one name flipping.** `:1448` tests
  `[ "$col6un" = "862" ]`; the true branch `printf`s `DISP MANIFEST_COL6_STATE` at `:1449`, which is
  **not counted**, and the false branch is `chk MANIFEST_COL6_RESIDUE_EQ_BINARIES` at `:1451`, which
  **is**. Two identifiers, one gated — an earlier cut of this file, and of two others, said one name
  flipping. The distinction is load-bearing: it is the *only* reason the state coordinate of a census
  total is discoverable by absence, since the counted name is simply not there until the fill lands.
- **Two hazards sit on that same line.** The discriminator is a **hardcoded `862`**, not
  `EXPECTED_UNIVERSE` at `:234`, so an unrelated tree bump can flip it; and a *partial* fill that
  leaves `col6un = 862` keeps the `DISP` forever. **Which makes the fill commit’s acceptance line
  “the `real` run prints 35 and `MANIFEST_COL6_STATE` is gone” — not “column 6 is filled”.**
  That 35 is this cut’s: if the floor commit has landed by then, § 6’s final note makes it 36, and a
  reader who holds 36 has not failed the test.
- **The `tag` coordinate** — 11 labels exist only under `tag=real` and 5 only without it (`:222`,
  `:259`, `:401`). This is the partition in § 6.
- **`run-real` artifact legs** — those 5 non-`real` names are gated on artifacts as well as on the
  tag: `:259` `[ "$TAG" != real ] && [ -f "$T3/run-real/universe.txt" ]`, with nested legs at `:277`
  (`generator.sha256`), `:285` (`inputs.sha256`) and `:402` (`predicate.sha256`). Four artifacts:
  **three `.sha256` tokens plus the universe path list** — not “four tokens”. These are the legs the
  two measurements below move.
- **`UNIVERSE_SHA_MATCHES_PIN`’s dual identity** — a `chk` under `real`, a `printf` of
  `DISP ` + the name at `:246` otherwise. So it prints on *every* run while being counted on one.

**And the consequence that reaches every count in this file: § 6’s partition is stated over `^SENT `
lines, not over names appearing anywhere in output.** The two differ by exactly the `DISP ` lines
above — a partition built by substring-matching a transcript would count a display as an assertion.

### The degraded states, measured

The claim this section exists to make good on is what a run prints when the `run-real` artifacts are
missing. It cannot be read off the source by a human without re-deriving the guard nesting, and when
first written this section **asserted it wrongly**: that such a run “prints 23 and still exits 0”.
It does not exit 0. `:292-294` and `:404-407` increment `FAILS_SENT` on the *unavailable* paths, which
emit no `SENT` line at all, and `:1589-1591` exits 1 whenever `FAILS_SENT > 0`. So the degraded run
fails — but **without a failed comparison**, which is a different and easier thing to miss: nothing
on its face says an assertion was skipped rather than run-and-broken.
