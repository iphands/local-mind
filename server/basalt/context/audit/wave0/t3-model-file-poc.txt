## bugs in this harness found by running it, not by reading it
  1. F2_SAME_META_SHORTCIRCUITS_EXTRACTION: two probes sharing identical `meta` bytes
     resolve to ONE cache dir, so the second extract_tokenizer() takes the
     existence-gated early return, writes NOTHING, and raises nothing - the caller scores
     it a pass. Discovered when a .claude/settings.json probe printed 'wrote' while the
     file did not exist. Every probe now carries a unique meta, and this assertion proves
     the short-circuit is live rather than assumed. F-2 silently disables F-1 probes.
  2. the git-visibility column first reported .claude/settings.json as 'untracked', not
     IGNORED: the harness overwrites HOME, core.excludesFile is ~/.gitignore, so git
     could not see the operator's global ignore file. Same command, different answer,
     because the environment moved. The git calls now restore the real HOME explicitly
     and use --no-optional-locks so a read-only query cannot refresh another repo's index.
  3. the reachability loop probed $HOME/prog/ai/local-mind/context/plans/RULES.md, which is
     not that file's path. It reported NO-PARENT/absent for a file that exists - a probe of
     nothing. Fixed; the row now reads 79/64 file(43709B). The conclusion (over budget) was
     unchanged, which is exactly why the bug survived: a wrong probe and a right answer look
     identical here.
  4. the harness wrote 13 __pycache__ files INTO THE AUDITED TREE (it imports the tree with
     cwd=vendor/basalt). git diff could not see them because /vendor/ is gitignored, so a
     whole session of 'AUDIT TREE OK' was true and useless. Caught by the census universe
     hash. Fixed with PYTHONDONTWRITEBYTECODE plus the POC_TREE_BYTECODE guard, and control D
     above exists to prove the guard is not decorative. Full record:
     wave0/t3-tree-contamination.txt.
